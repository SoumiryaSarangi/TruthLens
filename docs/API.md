# HTTP API

The server is a FastAPI application (`app/main.py`) listening on `127.0.0.1:8000`. It also serves the web page at `/` and
its files under `/static/`. There is no authentication: it is built to run on one machine, for one reader. Do not expose it
to a network without putting something in front of it (see [`SECURITY.md`](../SECURITY.md)).

Interactive OpenAPI documentation is generated by FastAPI at `/docs` and the schema at `/openapi.json`.

## `POST /verify`

Check one forwarded message. The message may hold up to three claims; each is verified separately.

**Request body** (`application/json`)

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `text` | string, 1 to 4000 characters | required | The message, in English, Hindi or Punjabi, native or Roman script. Normalised to Unicode NFC at the door. |
| `lang_hint` | string or null | null | Optional language hint. |
| `include_trace` | boolean | true | Include the stage-by-stage trace (timings and notes). |
| `live_search` | boolean | false | Send **this text** to Wikipedia and Google Fact Check. Explicit, per request: nothing is sent unless true. |
| `force_claim` | boolean | false | "Check it anyway": check a short fragment the claim gate refused. Ignored for a greeting. |

Query parameter `claim_idx` (integer, optional) selects a claim of a frozen evaluation split; the web page never sets it.

**Response** `200`

```jsonc
{
  "request_id": "e21ccd145972",
  "input": { "original": "...", "normalized": "...", "lang": "en", "script": "latn",
             "script_purity": 1.0, "transliterated": null },
  "checkworthy": true,
  "results": [ /* one ClaimResult per checked claim, at most 3 */ ],
  "unchecked_claims": [],                 // claims found but not checked (over the limit of 3)
  "trace": { "events": [ { "stage": "...", "impl": "...", "ms": 12.3, "note": "..." } ] }   // if include_trace
}
```

**`ClaimResult`**

| Field | Meaning |
| --- | --- |
| `claim` | `{claim_id, text, span}` the claim that was checked. |
| `path` | `"fast"` (a published fact-check matched), `"evidence"` (retrieval and stance), or `"none"` (not a claim). |
| `verdict` | `Supported`, `Refuted`, `Conflicting`, `NEI` (not enough evidence) or `NotAClaim`. |
| `abstained` | True when the system declines to commit. **Distinct from `NEI`.** Never show an abstained result as a verdict. |
| `confidence` | 0 to 1. Calibrated for the offline path; **not calibrated** for live results (the trace says so). Show the band from `/version`, not the number. |
| `match` | On the fast path: `{factcheck_id, score, verdict, title, url, publisher, lang, claim_text}`. |
| `passages` | Evidence passages with `stance`, `stance_prob`, `source` (`null` offline, `wikipedia`, `factcheck_live`), `url`, `title`, and for live passages the `premise` the models read. |
| `live_sources` | Sources actually consulted for this result when `live_search` was true. Empty means nothing was queried. |
| `similar_match` | A published fact-check that is probably about something similar: a suggestion, **never a verdict**. |
| `sources_disagree` | True when the live sources point opposite ways and no verdict is shown. |
| `gate_reason` | On `NotAClaim`: `greeting`, `too_short` or `no_content`. |
| `claim_en` | The English claim a live verdict was judged on. |
| `explanation`, `explanation_source`, `explanation_lang`, `cited`, `faithfulness` | The explanation. An abstained result always carries the template text, never generated prose. |
| `manipulation_flags` | Persuasion-technique flags, shown after the verdict is decided; they never move it. |

**Errors**

| Status | When |
| --- | --- |
| `422` | Empty or whitespace-only `text`, or longer than 4000 characters. |
| `500` | An unexpected failure. The page shows a retry. A failing optional stage degrades to a recorded note, not a 500. |

A live source that is down never turns into an error: the response keeps the offline answer and the trace notes
`degraded: ...`.

## `POST /explain_words`

The optional "which words mattered" view for a live `Supported` or `Refuted` verdict. It never changes the verdict.

| Field | Meaning |
| --- | --- |
| `claim` | The English claim the verdict was judged on (1 to 4000 characters). |
| `premise` | The source text the models read (1 to 4000 characters). |
| `verdict` | `Supported` or `Refuted`. Anything else is a `422`. |

Returns the top words of the claim by occlusion influence. `404` if there is nothing to explain; `503` if the models are
unavailable. Cost is paid only when requested.

## `GET /health`

```json
{ "status": "ok", "stages": { "retrieval": "hybrid:rrf@200:loaded", "stance": "xlmr_nli:loaded",
                              "generation": "indicbart:loaded", "matching": "bge_m3:loaded" } }
```

`status` is `degraded` when a stage reports `not_loaded`. The live-check models load in the background and are not part
of this list.

## `GET /version`

Returns `git_sha`, the served `pipeline_config` path, the `config` as described by `PipelineConfig.describe()` (including
which optional features are on), `tau_match`, `tau_abstain` and `confidence_bands` (`{"high": 0.60, "medium": 0.40}`). The
web page reads the band cut points from here and never hard-codes them.

## Conventions

- **Colour is never the only signal** in the web client: every verdict is also an icon and a word. Clients should do the
  same.
- **Do not recompute** a verdict, band or abstention from the raw fields; render what the server returns.
- The offline lean of an abstained evidence-path result may be shown, greyed, as a lean; it must never be presented as a
  verdict.
